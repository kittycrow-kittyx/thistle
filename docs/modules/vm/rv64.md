# vm/rv64

`Rv64` binds hosted `Sys` capabilities to canonical RV64 execution.

| Boundary | Operation or state |
| --- | --- |
| Kernel instance | `Kern.canonical.memory` and the process's allocated leader hart |
| Image validation | `thistleLoadThx` |
| Syscall buffers | `thistleGuestAccess`; inaccessible buffers return EFAULT |
| Guest registers and pages | Canonical hart and process tables |
| Filesystem and streams | Current `Sys` interface |
| File mapping reservations | `thistleMapHostDescriptor`, `thistleMapHostAnonymous`, `thistleRemapHostFile` and `thistleUnmapHostFile` |
| Frame reclamation | Native process reaping |
| Diagnostics | Section names decoded from the loaded image |

RV64 descriptor metadata and directory enumeration consult `Sys` descriptor methods. Relative directory descriptor paths use the directory's current canonical path rather than its original open name.

The bridge derives file mapping ranges from native records on demand. Byte transfers use retained inode authority, with shared write-back before unmap, replacement or exit. Successful exec releases old file mappings before the next image loads. Shared-page coherence and dirty tracking remain parity work.

Shared mapping flushes consume the native byte bitmap. Initial population and remap growth do not mark writes; remap flushes the original range before moving it.

Before guest execution, shared views refresh stale inode revisions. Dirty guest batches publish before host dispatch or scheduling another hart. Native early boundaries make same-process shared aliases observe a write before another instruction. Hosted syscall output publishes synchronously. This contract relies on the cooperative, non-threaded host embedding; a parallel native host transport needs independent coherence validation.

Linux syscall dispatch captures its six operands through `thistleHartGetX` on the issuing canonical hart before awaiting host I/O. This avoids repeated unchecked typed-array reads and keeps operands bound to their originating hart. Host write completion uses a named method with explicit session and hart parameters.
